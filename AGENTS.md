# AGENTS.md

nopCommerce 5.00 — open-source ASP.NET Core e-commerce platform (repo root is a source checkout, not a git clone). MVC Razor app, no SPA.

## Build & test

- SDK pinned by `global.json` to **.NET SDK 10.0.100** (`rollForward: latestFeature`). All projects target `net10.0`. README's ".NET 9" claim is stale — trust the csproj/global.json.
- CI (`.github/workflows/dotnet.yml`, branch `develop`): `dotnet restore src` → `dotnet build --no-restore -c Release src` → `dotnet test --no-build -c Release src`.
- Tests are NUnit (`AwesomeAssertions` + Moq). Run all: `dotnet test src`; single fixture: `dotnet test src --filter "FullyQualifiedName~OrderServiceTests"`.
- **Tests use an in-memory SQLite database (`Data Source=nopCommerceTest.sqlite;Mode=Memory;Cache=Shared`)** — no server needed. The static constructor of `BaseNopTest` (Tests/Nop.Tests/BaseNopTest.cs) bootstraps the whole service container and runs a full store installation with sample data, so first test execution is slow. Test classes inherit `BaseNopTest` and use `GetService<T>()`. Other DB connection strings (`Connections.resx`, partial `NopTestConfiguration`) are empty by default — do not assume SQL Server in tests.
- `Directory.Build.props` sets `ImplicitUsings=enable` and suppresses NuGet vulnerability warnings (NU1901–NU1904) repo-wide.

## Architecture

- **Libraries** (`src/Libraries`): `Nop.Core` (domain/entities), `Nop.Data` (EF Core + LinqToDb providers, FluentMigrator migrations), `Nop.Services` (business logic). **Presentation**: `Nop.Web` (MVC app: Controllers/Models/Factories/Views, `Areas/Admin` for admin, `Themes/`), `Nop.Web.Framework` (shared plumbing, tag helpers, base controllers). Plugins live in `src/Plugins` (30+).
- Entry point: `src/Presentation/Nop.Web/Program.cs`. DI is **Autofac** (opted in via `CommonConfig.UseAutofac`), with nopCommerce's `EngineContext`/`Singleton<>` statics on top.
- Service convention: **every public method is async with an `Async` suffix** (`GetAllCategoriesAsync`). New public service methods must follow this. Factories build view models; controllers stay thin.
- Admin controllers live in namespace `Nop.Web.Areas.Admin.Controllers`; admin views under `Areas/Admin/Views`.

## Configuration & first-run gotcha

- `App_Data/appsettings.json` and `App_Data/dataSettings.json` are **gitignored and generated by the installation wizard** on first run. A fresh checkout will not boot until the `/install` page completes (creates DB, admin account, optional sample data).
- DB providers: SQL Server (default), PostgreSQL, MySQL, SQLite. Provider + connection string live in `dataSettings.json`; `Nop.Data/DataProviders/` holds provider implementations.
- Runtime config is also read from `App_Data/appsettings.{Environment}.json` then environment variables (see `Program.cs`).

## Plugins (critical)

- `Nop.Web.csproj` **excludes `Plugins\**` and `Themes\**` from compilation** (`<Compile Remove="Plugins\**;Themes\**" />`). Plugins are discovered **at runtime** from `src/Presentation/Nop.Web/Plugins/<SystemName>/` via each plugin's `plugin.json` descriptor (e.g. `Nop.Plugin.Misc.Forums/plugin.json` → `SystemName: Misc.Forums`).
- The `Nop.Web/Plugins/` folder is gitignored; the only committed plugin is the source in `src/Plugins/`. To make a plugin available, build its project and place the output (dll + content + `plugin.json`) under `Nop.Web/Plugins/<SystemName>/` — `dotnet build` of the whole solution runs the `NopTarget` post-build step which copies plugin outputs there. `src/Build/ClearPluginAssemblies.proj` prunes stale plugin assemblies after build.
- `plugin.json` `SupportedVersions` must contain `"5.00"`. Plugin versions are `5.00.x`.
- Plugin source layout convention: `Domain/`, `Services/`, `Infrastructure/` (DI registrar), `Controllers/`, `Views/`, `Content/`, `plugin.json`. Plugins reference `Nop.Services` and implement `IPlugin` + per-type plugin interfaces (IPaymentMethod, IWidgetPlugin, …).

## Data layer & schema changes

- Schema changes use **FluentMigrator `ForwardOnlyMigration`** classes in `src/Libraries/Nop.Data/Migrations/` (including `Installation/SchemaMigration.cs`). Entity/table mapping lives in `Nop.Data/Configuration/` (EF `IEntityTypeConfiguration`). New tables need both a migration and a mapping. `upgradescripts/` contains old SQL upgrade paths — irrelevant for current-version work.
- Settings classes implement `ISettings` (in `Nop.Core/Configuration`); they are auto-registered via type discovery and stored in the DB, not appsettings.

## Frontend assets

- `Nop.Web` uses **Bootstrap 4** (public theme + admin; AdminLTE 3.2 for admin). Do not use Bootstrap 5 markup/classes.
- npm deps (in `Nop.Web/package.json`) are copied into `wwwroot/lib_npm/` by gulp (`Nop.Web/gulpfile.js`); bundles are generated into `wwwroot/bundles/`. Run `npm install` then `npx gulp` in `Nop.Web` only if you changed asset dependencies. Theme views are under `Themes/DefaultClean/`.

## Conventions & constraints

- File-scoped namespaces (`namespace X;`), implicit usings, `I*Service` + `*Service` pairs, `*ModelFactory`/`*Model` for MVC. Interfaces in the same file as... no — follow the existing per-file structure of the layer you edit.
- No formatter/linter config (no .editorconfig-driven analyzers beyond defaults) and no codegen — just `dotnet build` + `dotnet test`.
- Docker: root `Dockerfile` builds `NopCommerce.sln` then publishes `Nop.Web`; `docker-compose.yml` pairs it with SQL Server 2019.

## OpenHarmony sandbox build/test environment (this machine)

The stock `dotnet` CLI dies with SIGSYS in this sandbox (seccomp blocks `get_mempolicy`; no ICU assumed; OHOS only execs codesigned ELFs). Use the wrapper **`dotnet-ohos`** (`~/.dotnet/dotnet-ohos`): sets `DOTNET_ROOT`, `TMPDIR`, `DOTNET_EnableWriteXorExecute=0`, `LD_PRELOAD=libnuma-shim.so`, and codesigns build outputs. Mandatory build flags: `MSBUILDUSESERVER=0` + `-m:1` (MSBuild worker nodes crash on sandbox socket restrictions). Plugin projects need `-p:SolutionDir=$PWD/src/` at **both restore and build** (their `OutputPath`/references depend on `$(SolutionDir)`). `global.json` is pinned to SDK `11.0.100-dev` (the bundled `10.0.110-dev` cannot build this repo).

`dotnet test`/vstest cannot launch its testhost here (vstest resolves the dotnet path via `Process.MainModule` → `/proc/self/exe` returns the sandbox-untranslated `/data/service/...` path). Instead run the suite with the in-process NUnit runner at **`~/.dotnet/test-tools/nunit-runner.dll`** (source: `~/.dotnet/test-tools/nunit-runner-src.cs`), working directory = test bin, plus these pieces the OHOS .NET channel lacks:

- AspNetCore.App managed dlls → from the `Microsoft.AspNetCore.App.Runtime.linux-arm64` NuGet runtime pack, resolved by the runner's `AssemblyResolve` fallback (the `linux-ohos-arm64` channel ships no aspnetcore runtime at all).
- `e_sqlite3.so`/`libe_sqlite3.so` → copies of harmonybrew's musl `libsqlite3.so`, placed in the test bin (codesigned).
- `libSkiaSharp.so` → `SkiaSharp.NativeAssets.Linux.NoDependencies` `runtimes/linux-musl-arm64/native/`, copied to the test bin + codesigned (NuGet's RID-aware copy skips `linux-ohos-arm64`).
- ICU → `LD_LIBRARY_PATH=~/.harmonybrew/lib` and **unset** `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT` (harmonybrew ships libicuuc/libicui18n/libicudata 78). Note: `[GeneratedRegex(..., "en-US")]` fails under invariant mode — the three repo edits (CommonHelper.cs, Forums BBCodeHelper.cs/CSharpFormat.cs) remove the cultureName arg.
- tzdata → `TZDIR=~/.dotnet/test-tools/zoneinfo` (from the PyPI `tzdata` wheel; the device has no `/usr/share/zoneinfo`).

Full run (1102 tests, ~25 min — first run slower due to the BaseNopTest install bootstrap):

```sh
cd src/Tests/Nop.Tests/bin/Debug/net10.0
export DOTNET_ROOT=~/.dotnet TMPDIR=/data/storage/el2/base/tmp DOTNET_EnableWriteXorExecute=0
export LD_LIBRARY_PATH=~/.harmonybrew/lib LD_PRELOAD=$DOTNET_ROOT/libnuma-shim.so
export TZDIR=~/.dotnet/test-tools/zoneinfo
unset DOTNET_SYSTEM_GLOBALIZATION_INVARIANT
dotnet exec ~/.dotnet/test-tools/nunit-runner.dll ./Nop.Tests.dll            # all tests
dotnet exec ~/.dotnet/test-tools/nunit-runner.dll ./Nop.Tests.dll OrderServiceTests   # one fixture (substring)
```
